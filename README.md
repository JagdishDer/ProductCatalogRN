# Product Catalog — React Native (Task 3)

A small cross-platform product-detail app built for the **Mobile Developer Assessment, Task 3**. It demonstrates shared TypeScript application code, DummyJSON API integration, secure access-token persistence, and **custom native camera modules written in Kotlin (Android) and Swift (iOS)**.

> **Assessment scope:** This repository section is for **Task 3 only**, not the separate Android Kotlin or iOS Swift tasks. The login screen and secure session persistence are small extras; the evaluated core is the shared API layer and custom native camera bridge.
>
> **Verification note:** Update the [Build and test status](#build-and-test-status) section with actual results from your machine before submission. The documentation describes the intended implementation; it does **not** claim that an iOS or Android build has been verified by the author of this README.

## Features

- **Login UI:** username/password form, loading indicator, validation, and API error messages.
- **DummyJSON authentication:** `POST /auth/login` with demo credentials.
- **Secure session storage:** access token stored through `react-native-keychain` using iOS Keychain and Android Keystore-backed storage; restored at launch and checked via `GET /auth/me`.
- **Product details:** fetch and display product **ID 1** using `GET /products/1`, including image, title, category, price, and description.
- **Custom native camera:** `capturePhoto(): Promise<string>` exposed to JavaScript through a Kotlin Android module and a Swift iOS module (with Objective-C export/registration for the classic bridge).
- **Camera states:** handle permission denial, cancellation, unavailable camera, and failures; display the captured image from its local file URI.
- **Logout:** clear the stored access token and return to the login screen.

## Install and run

From the **React Native project root** (the directory containing `package.json`):

```bash
npm ci
```

If no lockfile is present, use `npm install` instead. The project needs `react-native-keychain` listed in its dependencies.

### Android

1. Start an emulator in Android Studio **Device Manager**, or connect an Android phone with USB debugging enabled.
2. In one terminal, start Metro:

   ```bash
   npm start
   ```

3. In another terminal, run:

   ```bash
   npm run android
   ```

To compile a debug APK directly:

```bash
cd android
./gradlew :app:assembleDebug
cd ..
```

Expected output location:

```text
android/app/build/outputs/apk/debug/app-debug.apk
```

The `CAMERA` runtime permission is requested before the system camera is opened. The app must show a meaningful error if permission is denied. The Android module additionally checks permission and prevents concurrent captures.

### iOS

On a Mac with a supported Xcode installation:

```bash
cd ios
bundle install
bundle exec pod install
cd ..
npm run ios
```

If your React Native template uses Swift Package Manager instead of CocoaPods, use the dependency setup generated by that template, not `pod install`.

Confirm the following native settings:

- `NSCameraUsageDescription` exists in the **app target's** `Info.plist`.
- `CameraModule.swift` and `CameraModuleBridge.m` belong to the **app target**.
- The module is exported as `CameraModule`, matching `src/native/Camera.ts`.
- Test real capture on an **iPhone**; the iOS Simulator has no physical camera and should show an unavailable-camera error without crashing.

| Purpose | HTTP request | Used by |
| --- | --- | --- |

## Architecture and implementation decisions

### Shared application layer

`App.tsx` manages session UI state. `src/api/client.ts` owns HTTP requests, `src/screens/` renders the UI, `src/types/` contains TypeScript models, and `src/native/Camera.ts` is the single JavaScript entry point for native photo capture. This keeps platform-specific camera code out of shared screens.

### Secure token lifecycle

1. The user signs in with the DummyJSON login endpoint.
2. On success, `tokenStorage.ts` saves the access token using `react-native-keychain`.
3. On app launch, the token is read from secure storage and verified with `/auth/me`.
4. A valid token opens the product screen; invalid or unauthorized tokens are cleared.
5. A transient network failure during session verification shows a retry option rather than silently deleting the token.
6. Logout clears the secure credential and navigates back to login.

The token necessarily exists briefly in JavaScript memory to make authenticated requests. Never log tokens, put them in analytics, or store them in AsyncStorage. **Token refresh is not implemented.**

### Android camera bridge

The Kotlin module implements `capturePhoto()` and launches the system camera using `MediaStore.ACTION_IMAGE_CAPTURE`. It creates a temporary `.jpg` in app cache, provides a scoped `content://` URI through `FileProvider` to the camera app, and resolves the JavaScript Promise with its app-local `file://` URI after capture. Denied permissions, failed captures, cancellation, and an unavailable activity reject the Promise.

Key native pieces:

- `CameraModule.kt` — React Native method and activity result handler.
- `CameraPackage.kt` / `MainApplication.kt` — manual module registration.
- `AndroidManifest.xml` — camera permission and FileProvider declaration.
- `res/xml/file_paths.xml` — camera cache directory mapping.

### iOS camera bridge

The Swift implementation checks camera availability and authorization, presents the system `UIImagePickerController`, writes a captured JPEG to a temporary local file, and resolves a Promise with the file URI. It rejects denial, cancellation, save errors, and unavailable-camera cases. A small Objective-C file exports the Swift methods to the classic React Native bridge.

### Scope and native-module choice

The app uses a **classic React Native bridge** for the custom camera module to fit the assessment time budget, while the project can otherwise use the New Architecture. This approach should be described as a short-term interoperability choice, not a complete Turbo Native Module implementation. A production follow-up would migrate the camera interface to the current typed Turbo Module APIs.

## How to use

1. Open the app; the login screen appears if no valid saved session exists.
2. Enter the demo credentials and select **Sign In**.
3. Product ID 1 loads with its title, category, image, price, and description.
4. Tap **Capture Photo**, grant camera permission, take a photo, and confirm the capture.
5. The captured image appears below the camera button.
6. Tap **Logout** to clear the secure session.
7. Restart the app to verify session restoration (when logged in) or the login screen (after logout).

## Known limitations / deliberately skipped

- Fixed product ID (`1`) instead of a product browser or navigation flow.
- No product add/edit/delete, category filtering, image annotation, or uploading photos: these are **not required for Task 3**.
- Captured photos are in temporary local storage and can be removed by the OS; no gallery save or persistent media library.
- No token refresh implementation; users may need to sign in again when the access token expires.
- No full automated device test suite or exhaustive native error-recovery coverage.
- Classic bridge rather than a typed Turbo Native Module; the choice prioritizes a minimal, reviewable working implementation.
- The assessment is a demo, not a production authentication or camera experience.

## Troubleshooting

**`file_paths.xml` XML parse failure**  
Check `android/app/src/main/res/xml/file_paths.xml` (not `android/app/build/intermediates/...`). Its contents should be valid XML, for example:

```xml
<paths xmlns:android="http://schemas.android.com/apk/res/android">
    <cache-path name="camera" path="camera/" />
</paths>
```

**Kotlin unresolved `currentActivity`**  
Check that the module uses the appropriate API for your installed React Native version (in this implementation, `reactApplicationContext.currentActivity`), then rebuild native Android code.

**`Camera native module is not registered`**  
Verify `CameraPackage()` is included in `MainApplication.kt`, the module exports the name `CameraModule`, and a new native build was installed. Reloading JS alone does not compile Kotlin or Swift changes.

**Permission denied**  
Check the Android `CAMERA` manifest entry and runtime permission, or iOS `NSCameraUsageDescription` and authorization flow. If permission was permanently denied, enable it in system Settings.

**iOS Simulator says camera unavailable**  
Expected: use a physical iPhone for camera capture testing.

**Session does not restore**  
Verify `react-native-keychain` was installed and linked, `tokenStorage.ts` consistently uses the same service name, and `/auth/me` returns success for the saved token.
